# MD Dog 1.1 App Store Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build, validate, and upload MD Dog 1.1 for iPhone and iPad to App Store Connect without submitting it for App Review.

**Architecture:** Preserve the approved working tree, run local release preflight checks, create a signed generic-iOS archive with automatic signing, inspect the archive, then use Xcode Organizer's authenticated App Store Connect upload flow. Treat upload acceptance or processing as the terminal state and do not change App Store review or release settings.

**Tech Stack:** Xcode 26.6, Swift 5, SwiftUI, StoreKit 2, `xcodebuild`, Xcode Organizer, App Store Connect

## Global Constraints

- Upload the iPhone and iPad app only.
- Use marketing version `1.1`.
- Start with build number `1`; increment it only if App Store Connect reports that build `1` already exists for version 1.1.
- Include the current uncommitted changes in `md dog/ContentView.swift` and `md dog/DonationStore.swift`.
- Do not create or upload separate macOS or visionOS builds.
- Do not submit the build for App Review.
- Do not change release date, phased release, pricing, or storefront settings.
- Preserve unrelated files and existing working-tree changes.

### Task 1: Freeze and verify the release candidate

**Files:**
- Inspect: `md dog/ContentView.swift`
- Inspect: `md dog/DonationStore.swift`
- Inspect: `md dog.xcodeproj/project.pbxproj`
- Inspect: `md dog/Assets.xcassets/AppIcon.appiconset/Contents.json`
- Inspect: `Donation.storekit`
- Inspect: `Localizable.xcstrings`
- No source file is modified in this task.

**Interfaces:**
- Consumes: approved working tree containing the two release changes.
- Produces: verified release coordinates `Mike-Yang.md-dog`, version `1.1`, build `1`, team `T7Y3W9A2RX`, and StoreKit product `md_dog.tip`.

- [ ] **Step 1: Record the exact working-tree scope**

Run:

```bash
git status --short
git diff --check
git diff --stat -- 'md dog/ContentView.swift' 'md dog/DonationStore.swift'
```

Expected: only the approved source changes and release documentation are present; `git diff --check` emits no errors.

- [ ] **Step 2: Confirm release identifiers and platforms**

Run:

```bash
rg -n 'MARKETING_VERSION|CURRENT_PROJECT_VERSION|PRODUCT_BUNDLE_IDENTIFIER|DEVELOPMENT_TEAM|SUPPORTED_PLATFORMS|TARGETED_DEVICE_FAMILY|INFOPLIST_KEY_ITSAppUsesNonExemptEncryption' 'md dog.xcodeproj/project.pbxproj'
```

Expected: version `1.1`, build `1`, bundle identifier `Mike-Yang.md-dog`, team `T7Y3W9A2RX`, target families `1,2,7`, and non-exempt encryption set to `NO`. The project also lists macOS and visionOS support, but the generic-iOS archive compiles only the iPhone and iPad app.

- [ ] **Step 3: Validate release data and app icons**

Run:

```bash
python3 -m json.tool Donation.storekit
python3 -m json.tool Localizable.xcstrings
python3 -m json.tool 'md dog/Assets.xcassets/AppIcon.appiconset/Contents.json'
sips -g pixelWidth -g pixelHeight -g hasAlpha 'md dog/Assets.xcassets/AppIcon.appiconset/image (1).png' 'md dog/Assets.xcassets/AppIcon.appiconset/image dark (1).png' 'md dog/Assets.xcassets/AppIcon.appiconset/image tinted (1).png'
rg -n 'md_dog\.tip' Donation.storekit 'md dog/DonationStore.swift'
```

Expected: each JSON file parses, each iOS icon is 1024 × 1024 with no disallowed alpha channel, and `md_dog.tip` matches between the StoreKit configuration and source.

- [ ] **Step 4: Build the release candidate without signing**

Run:

```bash
xcodebuild -project 'md dog.xcodeproj' -scheme 'md dog' -configuration Release -destination 'generic/platform=iOS' -derivedDataPath /tmp/md-dog-1.1-preflight CODE_SIGNING_ALLOWED=NO build
```

Expected: `** BUILD SUCCEEDED **`. Record warnings separately; treat only errors or App Store validation blockers as release-stopping.

### Task 2: Create and inspect the signed iOS archive

**Files:**
- Create: `/tmp/MD-Dog-1.1-1.xcarchive`
- Inspect: `/tmp/MD-Dog-1.1-1.xcarchive/Info.plist`
- Inspect: `/tmp/MD-Dog-1.1-1.xcarchive/Products/Applications/md dog.app/Info.plist`
- No repository source file is modified unless Apple rejects build `1` as a duplicate.

**Interfaces:**
- Consumes: verified coordinates from Task 1 and the Apple account already configured in Xcode.
- Produces: a signed App Store archive whose embedded app is `Mike-Yang.md-dog` version `1.1` build `1`.

- [ ] **Step 1: Confirm a usable Apple distribution identity is available**

Run:

```bash
security find-identity -v -p codesigning
```

Expected: at least one valid Apple Development or Apple Distribution identity associated with the configured team. If none is available, open Xcode Accounts and let automatic signing create or download the required identity before continuing.

- [ ] **Step 2: Create the signed archive**

Run:

```bash
xcodebuild -project 'md dog.xcodeproj' -scheme 'md dog' -configuration Release -destination 'generic/platform=iOS' -archivePath '/tmp/MD-Dog-1.1-1.xcarchive' -allowProvisioningUpdates archive
```

Expected: `** ARCHIVE SUCCEEDED **`. If Xcode reports malformed stale provisioning profiles but still archives successfully, retain the archive and continue; if signing fails, fix only the named certificate, profile, team, or entitlement problem and rerun this command.

- [ ] **Step 3: Verify archive metadata and signature**

Run:

```bash
/usr/libexec/PlistBuddy -c 'Print :ApplicationProperties:CFBundleIdentifier' '/tmp/MD-Dog-1.1-1.xcarchive/Info.plist'
/usr/libexec/PlistBuddy -c 'Print :ApplicationProperties:CFBundleShortVersionString' '/tmp/MD-Dog-1.1-1.xcarchive/Info.plist'
/usr/libexec/PlistBuddy -c 'Print :ApplicationProperties:CFBundleVersion' '/tmp/MD-Dog-1.1-1.xcarchive/Info.plist'
codesign --verify --deep --strict --verbose=2 '/tmp/MD-Dog-1.1-1.xcarchive/Products/Applications/md dog.app'
codesign -d --entitlements :- '/tmp/MD-Dog-1.1-1.xcarchive/Products/Applications/md dog.app'
```

Expected: identifier `Mike-Yang.md-dog`, version `1.1`, build `1`, a valid signature, and no unexpected entitlements.

### Task 3: Validate and upload through Xcode Organizer

**Files:**
- Consume: `/tmp/MD-Dog-1.1-1.xcarchive`
- No repository file is modified unless a duplicate build number requires the fallback in Step 4.

**Interfaces:**
- Consumes: signed archive from Task 2 and the signed-in Xcode App Store Connect account.
- Produces: App Store Connect upload acceptance for MD Dog 1.1.

- [ ] **Step 1: Open the archive in Xcode Organizer**

Run:

```bash
open '/tmp/MD-Dog-1.1-1.xcarchive'
```

Expected: Xcode Organizer opens with the MD Dog archive selected.

- [ ] **Step 2: Start App Store Connect distribution**

In Organizer, select **Distribute App → App Store Connect → Upload**. Keep automatic signing selected, include symbols when offered, and do not choose any export-only or direct-distribution option.

Expected: Xcode completes its validation stage and displays a summary identifying MD Dog 1.1 build 1.

- [ ] **Step 3: Upload and record Apple's result**

Confirm the upload in Organizer.

Expected: Xcode reports that the upload succeeded or that the build was delivered to App Store Connect for processing. Stop without opening or changing the App Review submission workflow.

- [ ] **Step 4: Handle only a duplicate-build rejection**

If Apple explicitly rejects build `1` because it already exists for version 1.1, modify both Debug and Release `CURRENT_PROJECT_VERSION` values in `md dog.xcodeproj/project.pbxproj` from `1` to `2`, verify with:

```bash
rg -n 'CURRENT_PROJECT_VERSION' 'md dog.xcodeproj/project.pbxproj'
```

Then repeat Task 1 Step 4 and Tasks 2–3 using `/tmp/MD-Dog-1.1-2.xcarchive`. Do not increment the build for any other class of failure.
